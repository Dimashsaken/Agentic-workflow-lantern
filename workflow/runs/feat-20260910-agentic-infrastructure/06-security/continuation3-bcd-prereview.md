## Gateway API cross-check

Official documentation describes `requestheaders` before the body is read, while a streamed `request` event occurs after the body was sent; therefore a late body hook cannot alone enforce the no-forwarding boundary. `server_connect` can reject a connection through its error field, and the ClientHello hook can influence whether upstream TLS is established first. These mechanisms need ordering and failure tests against the selected version. [Mitmproxy event hooks](https://docs.mitmproxy.org/stable/api/events.html).

The published option list explicitly may differ from the installed version; capture and validate the actual binary's effective options at startup. A documented option name is not proof the image accepted it. [Mitmproxy options](https://docs.mitmproxy.org/stable/concepts/options/).
